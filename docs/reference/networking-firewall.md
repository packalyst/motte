# Networking & Firewall

How the panel enforces network access at two layers: **L3** (an nftables ruleset generated by the Go backend and pushed into the kernel) and **L7** (a Traefik middleware plugin, "sentinel", that filters HTTP requests). This document explains the nftables model, how rules are generated and validated, the access toggles, Cloudflare handling, the VPN ACL, and the L7 plugin.

Related: [architecture.md](architecture.md) · [backend.md](backend.md) · [security.md](security.md) · [data-model.md](data-model.md) · [api-surface.md](api-surface.md) · [deployment.md](deployment.md) · [fleet-agent.md](fleet-agent.md)

> **The firewall is the gate.** Two governing invariants run through every file below:
> - **Never lock the operator out.** Loopback, the Docker bridge, the WireGuard subnet and the Headscale/Tailnet overlay are *always* trusted; the server's own IP is never auto-banned. When in doubt the code emits an **empty / permissive** table (**fail-open**) rather than risk dropping the management plane.
> - **Never wedge the ruleset.** Each table is applied atomically (delete + recreate in one script). A single malformed element (e.g. a stray IPv6 address in an `ipv4_addr` set) would make `nft` reject the *entire* script and silently drop every rule in that table — so every value is validated at the set boundary, and the script is checked before it is applied.

## 1. The nftables model

### 1.1 Four separate registered tables

Rather than one monolithic table, the panel registers **four independent `inet` tables**, each owning exactly one concern so it is obvious in `nft list ruleset` what does what, and each can be toggled/inspected on its own.

| Table | File | Purpose | Hook priority (kernel eval order) | Base-chain policy | Composition |
|---|---|---|---|---|---|
| `wgadmin_panel_access` | `api/internal/nftables/panel_access.go` | Close the API port (8081) to the public when `api_direct_access=off` | `input` **priority -10** | `accept` | drop-subset-terminal |
| `wgadmin_cf_only` | `api/internal/nftables/cf_only.go` | Restrict web ports 80/443 to Cloudflare edge (+ trusted) when `web_cloudflare_only=on` | `input` **and** `forward` **priority -10** | `accept` | drop-subset-terminal |
| `wgadmin_firewall` | `api/internal/nftables/firewall.go` | Main firewall: port allow-list, IP/range/country/ASN block+allow, per-peer WAN block, IPv6 drop, MSS clamp | `input` **priority 0**, `forward` **-1**, `output` **0** | `input`: **drop**; `forward`/`output`: **accept** | default-drop (input) / default-accept + explicit drops (forward, output) |
| `wgadmin_vpn_acl` | `api/internal/nftables/vpn_acl.go` | Peer-to-peer isolation, per-peer ACL rules, virtual-IP gating | `forward` **priority 0** | `accept` | default-deny backstop drops |

The **struct `Priority()`** value (panel_access=5, cf_only=6, firewall=10, vpn_acl=20; `service.go` sorts by it) only orders the *emission* of tables into the combined apply loop. What actually orders **kernel evaluation** is the **chain hook priority** in each `type … hook … priority N` line. Lower = earlier. So both toggle tables sit at `-10` (before the main firewall's `input` at `0`); the vpn_acl `forward` chain sits at `0` (after the main firewall's `forward` at `-1`).

**How they compose — why drop-subset, not accept:** `accept` in a base chain is **not terminal across tables** — another table's chain at the same hook still runs and can drop. A `drop` **is** terminal. So the two toggle tables never try to "accept" the API/web ports (that couldn't override the main firewall anyway); they only **add a `drop` for the untrusted subset**, which wins, and leave trusted traffic to be accepted by the main firewall's normal port allow-list. See the composition note in `panel_access.go` (top-of-file comment).

Registration (`api/cmd/main.go:188-195`): `firewall` table is registered from `firewall.New` (`service.go:94`); the other three are registered directly in `main.go`. All go through `nftables.Service.RegisterTable`.

### 1.2 Script generation — `BuildSet` / `BuildChain` / `TableHeader`

`api/internal/nftables/script.go` holds the safe primitives every table uses to emit an `nft -f` script. They validate and sanitize on the way out so a bad value cannot break the syntax:

- `TableHeader(family, name)` — emits `#!/usr/sbin/nft -f` + `table <family> <name> {`; validates family against `^(ip|ip6|inet|arp|bridge|netdev)$` and the name against the identifier regex (falls back to `inet` / `invalid_table`).
- `BuildSet(name, setType, flags, elements)` — emits a `set` block. Validates the name and `setType` (`ipv4_addr|ipv6_addr|ether_addr|inet_proto|inet_service|mark|ifname`), filters `flags` to `constant|interval|timeout|dynamic`, and **sanitizes every element** (`SanitizeElement` strips `\n \r ; { } #`). Special handling: `auto-merge` is **not** a flag keyword — it's pulled out and emitted on its own line, and **only** when `flags interval` is also present (otherwise `nft` rejects it and wedges the reload). `interval` + `auto-merge` also lets overlapping CIDRs coalesce instead of erroring.
- `BuildChain(name, chainType, hook, priority, policy, rules)` — emits `chain <name> { type <t> hook <h> priority N; policy <p>; … }`. Validates chainType (`filter|nat|route`), hook, policy (`accept|drop`), and strips newlines from each rule.

**Boundary guards (the anti-wedge invariants).** The panel is **IPv4-only** for its address sets. Values are filtered *before* they reach a set:
- `ValidateIPv4OrCIDR` (`script.go:49`) — rejects IPv6; used everywhere an address flows into a rule/set. The doc-comment spells out the stakes: a stray IPv6 value wedges the whole atomic table and (for vpn_acl) would flip peer isolation from default-deny to default-allow.
- `isValidPortElement` / `validPortNum` (`firewall.go:18-29`) — port must be `1-65535` or a strict `N-M` range, guarding the `inet_service` set boundary.
- `keepIPv4CIDRs` (`firewall.go:34`) — drops non-IPv4 elements from provider-sourced (country/ASN) ranges so a corrupt cache row can't wedge the reload.

### 1.3 `nft` validation and the atomic reload

`api/internal/nftables/service.go`:
- **Apply loop** (`ApplyAll`, line 116): snapshot the registered tables, sort by `Priority()`, and `applyTable` each in order. Any table error aborts the whole apply.
- **Atomic replacement** (`applyTable`, line 138): the built script is prefixed with `delete table <family> <name>\n`. `nft flush table` only clears *chains*, **not set elements**, so a `delete table` before the new definition guarantees clean state. If the delete fails (table doesn't exist yet) it retries without the prefix.
- **Reload** (`ApplyScript`, line 167): write the script to a temp file via `os.CreateTemp`, then `nft -f <file>`. `nft` parses the entire file and applies it as one transaction — either the whole table swaps in, or nothing changes and an error is returned. (The individual tables themselves also emit an idempotent `table …\ndelete table …\n\n` preamble — see panel_access/cf_only/vpn_acl — so a re-apply is always clean.)
- **Debounce** (`RequestApply`, line 79): callers request an apply; a 500 ms `AfterFunc` timer coalesces bursts (e.g. many blocks landing at once) into one reload, broadcasting `firewall:pending` → `firewall:applying` → `firewall:applied`/`firewall:error` over the `general_info` WebSocket channel.

> **Note on `nft -c`:** the codebase does not run a separate `nft -c` (check-only) pre-flight pass in `ApplyScript`; the safety model is instead **input validation at every set/rule boundary** (§1.2) plus the atomic single-transaction `nft -f` (a bad script fails as a whole and leaves the previous ruleset intact). The tests do dump-and-lint the generated scripts (`dump_for_lint_test.go`, `firewall_asn_test.go`, `cf_only_test.go`, `panel_access_test.go`). *(If you were told the runtime shells out to `nft -c` — it does not in this tree; the equivalent guarantee comes from boundary validation + atomic apply. Flagging as a divergence from the brief.)*

## 2. The main firewall table (`wgadmin_firewall`)

### 2.1 Set inventory

Built by `buildScript` (`firewall.go:391`). All are `ipv4_addr` except the two port sets (`inet_service`). Ranges/country/ASN sets carry `interval, auto-merge`.

| Set | Type | Fed from | Used in |
|---|---|---|---|
| `blocked_ips` | ipv4_addr | `firewall_entries` type=ip, action=block, inbound/both | input+forward `saddr … drop` |
| `blocked_ranges` | ipv4_addr (interval) | type=range, block, inbound/both | input+forward `saddr … drop` |
| `blocked_countries` | ipv4_addr (interval) | geolocation provider (blocked, inbound) | input+forward `saddr` drop (unless allow-exempt) |
| `blocked_asn` | ipv4_addr (interval) | geolocation provider (blocked ASN, inbound) | input+forward `saddr` drop (unless allow-exempt) |
| `blocked_ips_out` / `blocked_ranges_out` / `blocked_countries_out` / `blocked_asn_out` | ipv4_addr | same, but outbound/both direction | forward+output `daddr … drop` |
| `allowed_ips` | ipv4_addr | type=ip, action=allow | input+forward `saddr … accept` (full accept, before drops) |
| `allowed_ranges` | ipv4_addr (interval) | type=range, action=allow | same |
| `allowed_countries` | ipv4_addr (interval) | geolocation allowed countries | **exemption only** from geo/ASN drops (not an all-port accept) |
| `allowed_asn` | ipv4_addr (interval) | geolocation allowed ASNs | same exemption |
| `allowed_tcp_ports` / `allowed_udp_ports` | inet_service | `firewall_entries` type=port, action=allow, protocol | input `tcp/udp dport … accept` |
| `no_internet_peers` | ipv4_addr | `vpn_clients` where `block_internet=1` | forward `saddr … oifname WAN drop` |

### 2.2 Chains

**`input` (priority 0, policy drop)** — traffic *to* the server, matched by source:
1. `ct state established,related accept` — replies always flow (incl. ICMP PMTUD errors).
2. `iif lo accept` — loopback.
3. **External IPv6 drop.** The WAN NIC is auto-detected (`detectWANInterface`, `firewall.go:47`, reads `ip -4 route show default` every render so cable/wifi swaps self-heal). If found: `meta nfproto ipv6 iifname "<wan>" drop`, then `ip6 nexthdr icmpv6 accept` (keeps internal neighbour discovery). If **not** found → **fail closed**: accept only ND ICMPv6 types, then `meta nfproto ipv6 drop`. Why: the block/country sets are `ipv4_addr`, and the port rules are protocol-agnostic, so an unfiltered IPv6 packet to an open port would otherwise be accepted.
4. **`allowAndSaddrDropRules()`** (shared with forward, `firewall.go:376`, so the two chains can't drift):
   - `ip saddr @allowed_ips accept` / `@allowed_ranges accept` — explicit trusted hosts, **full accept before any drop**.
   - `ip saddr @blocked_ips counter drop`, `@blocked_ranges counter drop`.
   - `ip saddr @blocked_countries ip saddr != @allowed_countries ip saddr != @allowed_asn counter drop` (and the `@blocked_asn` twin). A country/ASN **allow** only *exempts* its sources from the geo/ASN drop — it is deliberately **not** an all-port accept (that would expose SSH/admin to a whole country); the traffic still has to pass the port allow-list. Specific IP/range blocks still win.
5. `ip protocol icmp accept` — **after** the drops, so a blocked source gets no ping reply at all.
6. `tcp dport @allowed_tcp_ports accept` / `udp dport @allowed_udp_ports accept`.
7. `limit rate 5/minute log prefix "FIREWALL_DROP: " drop` — log (rate-limited) then drop everything else. This log line is what the **`portscan` jail** parses (§4).

**`forward` (priority -1, policy accept)** — routed VPN traffic:
1. `tcp flags syn tcp option maxseg size set rt mtu` — **MSS clamp** to path MTU (fixes slow VPN throughput without per-client MTU tuning; non-terminating, SYN only).
2. `ct state established,related accept`.
3. Forwarded external-IPv6 drop (`oifname "<wan>"`) — so a peer can't reach the internet over IPv6 and bypass every IPv4 egress control. Skipped if WAN undetected (never emit an unscoped forward drop).
4. `allowAndSaddrDropRules()` (same block as input).
5. `ip daddr @blocked_*_out drop` — block bad **destinations**.
6. Per-peer WAN egress block: `ip saddr @no_internet_peers oifname "<wan>" drop` — only when WAN is known and the set is non-empty (an unscoped rule would kill peer↔peer too).
7. `iifname "wg0" ct state new log prefix "VPN_TRAFFIC: " accept` / `oifname "wg0" accept` (and the `tailscale0` twins).

**`output` (priority 0, policy accept)** — from the server, matched by destination: `ct established,related accept` + the four `ip daddr @blocked_*_out drop` rules.

### 2.3 Overlap cleanup

`cleanOverlappingRanges` (`firewall.go:265`) runs before each build: deletes any **blocked** range fully contained in a larger blocked range (redundant in the drop set). Scoped to `action='block'` only — an **allow** range is an intentional exception that may deliberately sit inside a broader block, so it is never merged.

## 3. How ports get opened

Three sources feed `allowed_tcp_ports` / `allowed_udp_ports`, all landing as rows in `firewall_entries` (type=port, action=allow):

1. **Essential ports** — `api/configs/essential-ports.json`, loaded by `helper.BuildEssentialPorts` and inserted `INSERT OR IGNORE` with `source='system'`, `essential=1` at service init (`ensureEssentialPorts`, `service.go:130`). These cannot be removed via the API (`handleRemovePort` refuses `essential=1`).

   | Port | Proto | Service |
   |---|---|---|
   | 80 / 443 | tcp | Traefik HTTP / HTTPS |
   | 8080 | tcp | Traefik Dashboard |
   | 8081 | tcp | API |
   | 8083 | tcp | AdGuard UI |
   | 8443 | tcp | DERP HTTP |
   | 51820 | udp | WireGuard |
   | 3478 | udp | STUN/DERP |
   | 53 | udp | DNS |

2. **Docker-published ports** — `SyncDockerPortsToDB` (`ports_handlers.go:313`) queries the Docker API for containers publishing to `0.0.0.0`/`::`, then **deletes all `source='docker'` rows and re-inserts** the currently-published set. So a stopped container drops its allow rule; `source='manual'`/`'system'` rows are never touched. Disabled if `AUTO_DISCOVER_DOCKER_PORTS=false`. Other packages call `Service.SyncAndReapply()` (`service.go:36`) after publishing/removing container ports (e.g. turbotunnels).
3. **Manual ports** — `handleAddPort` (`source='manual'`), and the SSH-port change flow (`handleChangeSSHPort`, `ports_handlers.go:146`) which adds the new port as essential, applies, edits `sshd_config` via `nsenter … systemctl restart sshd`, then removes the old port — with rollback at each step.

**Blocks & allows** are `firewall_entries` rows too (type ip/range/country/asn, action block/allow). The unified entries API lives in `entries_handlers.go`; auto-blocks come from jails (§4). See [api-surface.md](api-surface.md) for the endpoint list and [data-model.md](data-model.md) for the `firewall_entries` schema.

## 4. Jails (brute-force protection)

`api/internal/firewall/jail.go` — a fail2ban-style log watcher. Each enabled row in `jails` gets a monitor goroutine (`startJailMonitor`) that tails a log file and, on a regex match, records the source IP; when an IP hits `max_retry` within `find_time` seconds it is auto-blocked for `ban_time` (`blockIP` → `firewall_entries`, then `RequestApply`).

**Default jails** (`ensureDefaultJails`, `jail.go:238`):

| Jail | Log file | Match | max_retry / find_time / ban_time |
|---|---|---|---|
| `portscan` | `/var/log/kern.log` | `FIREWALL_DROP:.*SRC=(ip).*DPT=(port)` (the input-chain drop log) | 10 / 3600 / 2592000 |
| `sshd` | `/var/log/auth.log` | `Failed password.*from (ip)` | 5 / 3600 / 2592000 |
| `turbotunnels` | turbotunnels auth-fail log | `TURBOTUNNELS_AUTH_FAIL SRC=(ip)` | 5 / 3600 / 2592000 |

Safety in `blockIP`/`blockIPWithOptions` (`blocking.go:33`): IPv6 values are skipped (IPv4-only sets); the server's own IP and `127.*` are never auto-banned (a spoofed log line must not lock the panel out). The `portscan` jail also skips the WireGuard port.

**Escalation** (`blocking.go`): optionally block a whole `/24` (`checkEscalation`) or a whole ASN (`checkASNEscalation`) when enough distinct IPs from it are banned in a window. ASN escalation has a **size floor** (`maxAutoEscalateASNAddrs = 1<<16`) so an attacker rotating IPs through a cloud/CDN can't force a massive collateral block — a large ASN can still be blocked manually.

## 5. The two L3 access toggles

Both are **fail-open**: if disabled, or if the code can't safely classify traffic, they emit an **empty shell table** so they can never drop the management plane. Both toggle-driven re-applies are wired through `settings.RequestFirewallApply` (`main.go:200`) so flipping the setting takes effect live.

### 5.1 `api_direct_access` — close the API port (`wgadmin_panel_access`)

- **ON (default):** empty table — the API (port `API_PORT`, e.g. 8081) stays reachable by direct IP. Required before a domain is configured (IP is the only way in).
- **OFF:** an `input` chain at **priority -10** (before the main firewall) that drops the API port from the public internet but **accepts it from trusted sources** first, then `limit rate 5/minute log prefix "PANEL_ACCESS_DROP: "` and `tcp dport <port> drop`.

`restrictEnabled` is true **only** when the setting is explicitly `"off"`; a missing setting or any read error → don't restrict (safe default for a fresh, domain-less install). Also fails open if the port can't be parsed or the trusted list is empty.

### 5.2 `web_cloudflare_only` — restrict 80/443 to Cloudflare (`wgadmin_cf_only`)

- **OFF (default):** empty shell — 80/443 open to everyone.
- **ON:** **two** chains at **priority -10**, both accepting 80/443 from the trusted local sources + `::1`, then from `@cf_v4` / `@cf_v6` (the live Cloudflare set, §6), then `limit rate 5/minute log prefix "CF_ONLY_DROP: "` and dropping 80/443 from everything else. The shared rule builder is `cfRules(v4, v6, trusted, prefix)`:
  - **`input`** chain — for any host-networked service that binds 80/443 directly.
  - **`forward`** chain — **essential**: Traefik runs in a container, so its 80/443 are Docker-*published* ports. That traffic is DNAT'd and traverses the `forward` hook, **never `input`** (see `firewall.go:457`). The forward rules are prefixed with **`ct status dnat`** so only externally-published traffic is filtered — WireGuard and container-to-container forwarding are untouched. (An input-only version silently did nothing for Traefik — the panel stayed reachable by raw IP.)

`restrictEnabled` is true **only** when the setting is explicitly `"on"`. Fails open if the Cloudflare list is somehow empty (never risk dropping all web traffic). Enabling is gated by the panel on the domain being proxied through Cloudflare — persisted at setup as `BEHIND_CLOUDFLARE` and surfaced as `web_cloudflare_only_available` (see [security.md](security.md)).

### 5.3 Trusted sources that are never dropped

`trustedPanelSources()` (`panel_access.go:120`, shared by both toggle tables) always returns:

| Source | Env var | Fallback |
|---|---|---|
| Loopback | — | `127.0.0.0/8` |
| Docker bridge (so Traefik keeps proxying) | `DOCKER_SUBNET` | `172.18.0.0/24` |
| WireGuard admins | `WG_IP_RANGE` | `10.8.0.0/16` |
| Headscale/Tailnet admins | `HEADSCALE_IP_RANGE` | `100.64.0.0/16` |

Each env value is validated (`validCIDROr`); a garbled var falls back to the `.env.example` default so a trusted source is never silently lost.

## 6. Cloudflare handling

Two **distinct** mechanisms — do not conflate them:

### 6.1 The live CF CIDR list (access control) — `api/internal/helper/ip.go`

- `defaultCloudflareCIDRs` (line 142) — bundled fallback (~15 v4 + ~7 v6 ranges) used at boot and whenever a refresh fails.
- `StartCloudflareIPUpdater(ctx)` (line 212, started in `main.go:93`) — on boot and **every 24h**, fetches `https://www.cloudflare.com/ips-v4` and `…/ips-v6`. A **sanity floor** rejects a response with `< 10` ranges (bad/partial fetch) and keeps the current list. On success it swaps `cloudflareCIDRsStore` (an `atomic.Value`, read lock-free on the request hot path) and calls the **update hook**.
- `SetCloudflareUpdateHook(fn)` (line 183) — `main.go:203` registers `nftSvc.RequestApply`, so after every successful refresh the `wgadmin_cf_only` table rebuilds its `@cf_v4`/`@cf_v6` sets from the fresh list. `CloudflareCIDRs()` (line 167) is what `cf_only.go` reads.
- `isCloudflareIP(ip)` (line 196) — membership test used by `GetClientIP` (below).
- **It never fails closed** — any failure keeps the last-good list (defaults at minimum).

### 6.2 `forwardedHeaders.trustedIPs` (header-trust) vs the `cf_only` table (access control)

These solve different problems and must not be confused:

- **`cf_only` table** = **access control**: who may *reach* ports 80/443 at L3 (§5.2). Restricting to Cloudflare here means nobody can bypass Cloudflare by hitting the raw server IP.
- **Header-trust** = deciding whether to *believe* `CF-Connecting-IP` / `X-Forwarded-For` when computing the real client IP. In this codebase that trust is enforced in the **Go API** via `TRUSTED_PROXIES` → `helper.InitTrustedProxies` (wired in `auth/ratelimit.go:71`) and `GetClientIP` (`ip.go:110`): forwarding headers are honoured **only** when the immediate peer is a trusted proxy, and `CF-Connecting-IP` is trusted **only** when the last hop is a Cloudflare edge IP (so a bypasser can't forge a client IP). With no trusted proxies configured it **fails closed** (ignores headers), so a direct caller can't spoof its IP.
  - **Divergence from the brief:** the current `traefik/traefik.yml.template` does **not** set an `entryPoints.*.forwardedHeaders.trustedIPs` (Traefik reads the API over the Docker bridge via `host.docker.internal`). The `forwardedHeaders.trustedIPs` knob is referenced only in a code comment (`api/internal/logs/sources/traefik.go:46`) describing what happens when it isn't set: `ClientHost` already equals the proxy edge IP, so the header wins in `realClientIP`. Treat header-trust as an **API-side** concern here, not a Traefik static-config one. *(Flagged as unverified against the brief's wording.)*

### 6.3 CF-awareness in the L7 plugin

The sentinel plugin (§8) has its **own** copy of the Cloudflare CIDR list (`sentinel.go:744`, `cloudflareCIDRs` + `isCloudflareIP`) because a Traefik local plugin can't import the API's helper. Its `getClientIP` (`sentinel.go:728`) trusts `CF-Connecting-IP` only when the connecting peer is a Cloudflare edge IP — otherwise the connecting peer *is* the client (e.g. a VPN client over the tunnel). This is what makes VPN-only mode un-spoofable.

## 7. The VPN ACL (`wgadmin_vpn_acl`) and virtual IPs

`api/internal/nftables/vpn_acl.go` — a single `forward` chain (priority 0, policy accept) whose **default-deny backstop** at the bottom isolates peers unless an explicit rule allows them. Data comes from `vpn_clients` (with `acl_policy`), `vpn_acl_rules`, and `vpn_virtual_ips` (+ `vpn_virtual_ip_acl`).

Rule emission order (top = evaluated first):
1. `ct state established,related accept` — replies to inbound-initiated flows (incl. ICMP errors). **No blanket `ip protocol icmp accept`** — ICMP obeys the same ACL as every other protocol, so isolated peers can't be pinged and can't ping out.
2. **`block_all` peers** — explicit `ip saddr <ip> drop` + `ip daddr <ip> drop` before any accept.
3. **`allow_all` peers** — blanket accept to/from the whole `WG_IP_RANGE` and `HEADSCALE_IP_RANGE`, but carved out with `ip daddr != @vips` / `ip saddr != @vips` so a vip obeys **only** its own rules, never an allow_all peer's range-wide accept.
4. **Explicit `vpn_acl_rules`** — `ip saddr <src> ip daddr <dst> accept` (+ reverse if bidirectional), de-duplicated, skipping pairs already covered by allow_all/block_all.
5. **Virtual IPs** (`@vips` set of IPv4 vip addresses):
   - **Quarantine** vips: drop traffic the vip (and its DNAT `target` LAN IP) *initiates* toward peers — it may be reached but must not initiate. (ct established at the top still lets replies through.)
   - **Restricted** vips: `ip saddr <allowed-peer> ip daddr <vip> accept` for each allowed source; a restricted vip with no allowed sources emits nothing → stays unreachable (secure default).
   - **Open** vips: `ip daddr <vip> accept` for any peer.
6. **Default-deny backstop** — `ip saddr <range> ip daddr <range> drop` symmetric across wg↔wg, wg↔hs, hs↔hs. Since vips sit inside the WG range, this drop is what makes them unreachable by default (the accepts above open them).

**Fail-closed when a range is missing/invalid:** if `WG_IP_RANGE`/`HEADSCALE_IP_RANGE` can't be validated, the IP-based backstop can't be emitted and the chain policy is `accept` — which would void all isolation. So the code falls back to **interface-scoped** drops: `iifname "wg0" oifname "wg0" drop` (and the `tailscale0` twin), denying same-interface peer↔peer while leaving internet-bound (WAN-egress) traffic alone. `ValidateIPv4OrCIDR` gates every address before it is emitted.

See [data-model.md](data-model.md) for the `vpn_clients` / `vpn_acl_rules` / `vpn_virtual_ips` schemas and the [Virtual IPs feature design] for the product intent (expose a LAN device over WG).

## 8. L7 — the Traefik "sentinel" plugin

`traefik/plugins-local/src/local/sentinel/sentinel.go` — a self-contained Traefik middleware (registered as a local plugin in `traefik.yml.template`, `experimental.localPlugins.sentinel`). It filters **HTTP** requests where L3 can't help (behind Cloudflare, nftables only sees the edge IP).

**Checks, in `ServeHTTP` order** (`sentinel.go:542`): maintenance → robots.txt → IP allow-list → **IP deny-list** → user-agent → header validation → time-of-day.

**The three roles it plays for this panel** (middlewares in `dynamic.yml.template`):

| Middleware | Config | Used by |
|---|---|---|
| `sentinel_fw_block` | `denyListURL: …/internal/blocklist`, `denyCacheTTL: 300`, `blockReportURL: …/internal/l7block`, `errorMode: silent` | `ui`, `unified-api` routers — enforces the panel's block list at L7 |
| `sentinel_vpn` / `sentinel_vpn_silent` | `ipFilter.sourceRange: <VPN ranges>` | `headscale-api-blocked` — VPN-only access |
| `sentinel_drop` | `sourceRange: ["0.0.0.0/32"]`, silent | `catchall-drop`, `block-pwa-catchall` — silently close unknown domains |
| `sentinel_robots` / `sentinel_deny_agents` | remote AI-bot / crawler lists | optional bot blocking |

**Firewall block-list at L7 (`sentinel_fw_block`).** The API serves the same blocked-source data over the internal Docker network at `GET /internal/blocklist` (`firewall/blocklist_internal.go:75`, plain text, one CIDR/IP per line), assembled by `AllBlockedCIDRs` (explicit ip/range blocks + expanded country + ASN CIDRs — the same data that feeds the nftables sets). The plugin fetches and caches it (`denyCache`, 300 s), parses it into an `ipDenySet` (exact IPs in a map, CIDRs in a slice), and drops any request whose **real client IP** (Cloudflare-aware `getClientIP`) is in the list.

- **Fail-open:** if the list can't be fetched, `fetch()` returns nil and nothing is denied — a list outage never locks anyone out (`sentinel.go:571`, `dynamic.yml.template` comment).
- **Internal-only endpoints:** both `/internal/blocklist` and `/internal/l7block` **refuse any request carrying `CF-Connecting-IP` / `X-Forwarded-For` / `X-Real-IP`** (those only appear on public-edge traffic) → answer direct internal calls only. Unauthenticated by design (not routed by Traefik; the data isn't secret).

**L7 block metrics.** Silent drops leave no access-log trace, so the plugin POSTs a periodic best-effort `{"count":N}` (every ≥20 s, `recordDrop`, `sentinel.go:393`) to `POST /internal/l7block` (`firewall/l7stats.go`), stored in `l7_block_samples`. Fire-and-forget — a failed report never affects blocking.

**Blocked-by-layer view.** `firewall/layers.go` (`GET /api/fw/layers?period=…`) sums three enforcement layers for a window: **L3** = sampled nftables packet drops (`l3stats.go`; because the table is rebuilt on every apply the kernel counters reset, so a sampler stores *deltas* every 20 s into `fw_drop_samples`), **DNS** = blocked DNS queries from `logs`, **L7** = `l7_block_samples`. `handleClearStats` zeroes only the chart tables — enforcement (`firewall_entries` + live nftables sets) is untouched.
